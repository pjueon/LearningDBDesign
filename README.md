# DB 설계 첫걸음 — 동백커피로 배우는 정규화·제약·스키마 진화

DB를 다뤄 본 경험이 거의 없고 SQL은 기초 문법만 훑은 개발자(C++와 Python을 읽는 독자)를 위한 관계형 DB 설계 교재입니다.
SQL 문법 교재가 아니라 "요구사항이 바뀌어도 버티는 스키마를 어떻게 고르는가"를 판단하게 만드는 것이 목표입니다.
가상의 카페 "동백커피"가 1호점에서 가맹점으로 늘어나는 과정을 따라가며, 앞 장에서 만든 스키마가 뒷 장의 새 요구(옵션, 가격 변경, 데이터량, 동시 주문, 가맹점)를 만나
깨지고 고쳐지는 구조로 쓰였습니다. 장 하나는 HTML 파일 하나이고, 장 안은 화면 단위로 넘겨 읽습니다. 코드는 PostgreSQL 기준 SQL입니다.

## 여는 법

`docs/index.html`을 더블클릭해서 브라우저로 엽니다. 서버나 설치는 필요 없고 `file://`로 동작합니다.
화면은 방향키(← →)나 아래쪽 버튼으로 넘기고, 읽은 위치는 그 브라우저에 저장됩니다.

## 스키마는 이렇게 자랍니다

엑셀 한 장(1장) → v1 표 4개(2장) → v2 정규화 검증, 표 변경 없음(3장) → v3 제약조건(4장) → v4 옵션·세트(5장) → v5 스냅샷·가격 이력·쿠폰·멤버십·포인트 원장(6장)
→ v5.1 인덱스와 일 매출 요약(7장) → v6 재고·레시피·픽업 슬롯(8장) → v7 매장·매장별 메뉴와 가격, 표 25개(9장).

## 직접 돌려 보기

교재에는 실행 파일을 넣지 않았습니다. 직접 해 보려면 **빈 PostgreSQL 데이터베이스**에 `authoring/02-스키마-정본.md`의 "v7 (9장 후)" 절의 SQL 블록 네 개를 위에서 아래 순서로 붙여 넣으세요. 표 25개가 만들어집니다(첫 블록이 `btree_gist` 확장을 켜므로 확장 모듈이 설치된 PostgreSQL이어야 합니다).
같은 방식으로 v1·v3·v4·v5 절도 단독으로 실행되지만 여러 절을 이어서 실행하면 `already exists` 오류가 납니다. v2 절은 DDL이 없고(v1과 같음), v5.1·v6 절은 앞 버전 위에 더하는 조각이라 빈 DB에서는 실행되지 않습니다. "이전 스크립트" 절도 앞 버전의 DB에서 시작하는 것입니다.
5~9장의 본문 SQL은 PostgreSQL 18 계열에서 실행해 확인한 기록이 `authoring/03-집필-절차.md`에 있고, 버전에 따라 동작이 다른 곳(예: 9장의 `ADD COLUMN` 기본값과 인덱스 skip scan)은 본문에 적어 두었습니다.
SQLite는 권하지 않습니다. 외래키를 기본으로 강제하지 않고 타입이 느슨하며 `SELECT ... FOR UPDATE`가 없어서, 본문 DDL을 붙여 넣으면 "제약이 막아 주지 않는다"는 잘못된 교훈을 얻기 쉽습니다.
