# 집필 절차 (저자용)

새 장을 쓸 때 이 문서만 보고 시작할 수 있어야 한다. 독자용 문서가 아니다.

읽는 순서: `00-기획.md`(무엇을 왜) → `01-커리큘럼.md`(그 장에 무엇이 들어가는지) →
`02-스키마-정본.md`(그 시점의 DDL. 2장 집필 전에 만든다) → 이 문서(어떻게 쓰고 검증하는지).
스킬 원문 규약(R1~R8)과 부품 목록은 `ch-template.html` 이 진실 원천이다.

---

## 1. 새 장 집필 절차

1. **커리큘럼에서 그 장의 항목·화면 수·시간을 확인한다.** 바꿔야 하면 `01-커리큘럼.md` 의
   장별 표기와 §3 합계표를 **함께** 고치고 §4.1 로 검산한다.
2. **스키마 정본에서 그 시점의 DDL 을 확인한다.** 정본과 다른 DDL 을 쓰려면 정본을 먼저 고치고
   변경 이력 표에 한 줄 남긴다. 이미 쓴 장에 영향이 있으면 그 장도 고친다.
3. **앞 장들이 남긴 빚(D1~D5)과 `.later` 표시를 찾는다.**
   `grep -o '"later">[^<]*' docs/ch*.html` 로 뽑아 이번 장이 갚을 것을 확인한다.
4. **화면 목록(제목 + 한 줄)을 먼저 적고** 본문을 쓴다.
5. `docs/chNN.html` 을 쓴다. 첫 장은 `ch-template.html` 을 복사하고, 이후는 직전 장을 복사하는 편이 빠르다.
6. **`book.js` 의 `BOOK` 에서 그 장에 `ready: true` 를 켠다.** 화면 수·시간은 커리큘럼과 이미 맞춰져 있다.
   (`_smoke` 는 `ch00` 을 현재 장으로 삼는다. 0장이 `ready` 가 아니면 "현재 장 표시" 가 FAIL 이다.)
7. 앞 장 마지막 화면의 `.chapter-end` 링크를 이번 장으로 바꾼다.
8. 새로 등장한 용어를 `TERMS` 에 추가하고 본문에서 `<span class="term" data-term="...">` 로 연결한다.
9. §3 검증과 §4 검산을 돌린다. 통과하지 못한 장은 완료로 보고하지 않는다.
10. **보고하고 멈춘다(R8).** 커밋은 저자가 요청할 때만 한다. 멀티라인 한글 커밋 메시지는 scratchpad 에
    파일로 쓰고 `git commit -F <파일>`. Co-Authored-By 줄은 넣지 않는다.

## 2. SQL 코드 규약

- **키워드는 대문자**(`SELECT`, `CREATE TABLE`, `PRIMARY KEY`), **식별자는 소문자 snake_case**.
  `book.js` 의 하이라이터가 대소문자를 구분해서 소문자 키워드는 칠해지지 않는다.
- 주석은 `--`. (`#` 는 Python 용으로 남아 있을 뿐 SQL 주석이 아니다.)
- 테이블 이름에 예약어 `order` 를 쓰지 않는다: `orders`, `order_line`.
- 새 SQL 키워드를 쓰게 되면 `book.js` 의 `PY_KW` 에 대문자로 추가한다. 추가 뒤 `_smoke` 를 다시 돌린다.
- 방언 차이가 학습에 영향을 주면 "다른 DB 에서는" 접힌 상자(`details.fold`)로 알린다.
- `<pre>` 안의 `<` `>` `&` 는 `&lt;` `&gt;` `&amp;` 로 쓴다(`>=` 는 `&gt;=`).
- 20줄 넘는 코드에는 `ol.notes` 행별 해설. 행 번호는 §3.4 로 대조한다.

## 3. 검증 (헤드리스 Chrome, Windows/Git Bash)

브라우저: `"/c/Program Files/Google/Chrome/Application/chrome.exe"` (Edge 도 된다).
**파일 경로는 두 종류를 구분한다** — Chrome 인자는 `file:///E:/study/DB/...`, 셸은 `/e/study/DB/...`.
Windows 파이썬은 `/c/...` 경로를 못 읽으므로 출력 파일 검사는 `grep` 을 쓴다.

### 3.1 런타임 점검 — `authoring/_smoke.html`

`book.css`·`book.js` 를 고칠 때마다 돌린다(하이라이터 키워드 추가 포함). 기대값: `실패 0건 / 전체 35건`.

```bash
CH="/c/Program Files/Google/Chrome/Application/chrome.exe"
"$CH" --headless=new --disable-gpu --no-sandbox --virtual-time-budget=4000 \
  --dump-dom "file:///E:/study/DB/authoring/_smoke.html" > out.html
grep -E "^FAIL|실패 [0-9]+건" out.html
```

`_smoke.html` 은 `../docs/assets/` 를 참조한다. `TERMS` 의 `_smoke` 항목은 지우지 않는다.

### 3.2 새 장 점검 — 임시 probe

`references/authoring.md` 의 probe 스크립트를 장 파일 **사본**의 `</body>` 앞에 붙여 열고
`<pre id="probe-out">` 를 읽는다. 기대값: `NO-OVERFLOW screens=<커리큘럼 값> termsMissing=0`.
가로 넘침이 나오면 코드 줄을 줄인다(약 90자). 레이아웃을 넓히지 않는다.

```bash
"$CH" --headless=new --disable-gpu --no-sandbox --virtual-time-budget=6000 --window-size=1280,1250 \
  --dump-dom "file:///E:/study/DB/<사본 경로>/chNN-probe.html" | grep -o "NO-OVERFLOW[^<]*\|OVERFLOW[^<]*"
```

### 3.3 눈으로 확인

```bash
"$CH" --headless=new --disable-gpu --no-sandbox --virtual-time-budget=9000 --window-size=1280,1400 \
  --screenshot=shot.png "file:///E:/study/DB/docs/chNN.html#s5"
```

위젯(이상현상 시뮬레이터, B-tree 스텝퍼, 동시성 타임라인)은 **조작한 뒤의 상태**를 스크린샷으로 확인한다.
헤드리스는 기본이 다크 모드다.

### 3.4 코드 해설의 행번호 대조 — 가장 자주 틀린다

`ol.notes` 의 `<span class="ln">N행</span>` 은 실제 코드와 대조한다. `<pre>` 안의 `<code>` 만 뽑는다
(인라인 `<code>` 까지 잡히면 수백 개가 나온다).

```python
import io, re
s = io.open('docs/ch03.html', encoding='utf-8').read()
out = []
for n, m in enumerate(re.finditer(r'<pre>.*?<code>(.*?)</code>\s*</pre>', s, re.S), 1):
    out.append('===== 코드 블록 %d =====' % n)
    for i, l in enumerate(m.group(1).rstrip('\n').split('\n'), 1):
        plain = re.sub(r'<[^>]+>', '', l).replace('&lt;', '<').replace('&gt;', '>')
        out.append('%3d| %s' % (i, plain))
io.open('lines.txt', 'w', encoding='utf-8').write('\n'.join(out))
```

## 4. 검산

### 4.1 커리큘럼 합계

장별 `**화면 N · M시간**` 표기의 합과 §3 합계표(129화면 · 23.5시간)가 일치해야 한다.

```python
import io, re
s = io.open('authoring/01-커리큘럼.md', encoding='utf-8').read()
rows = re.findall(r'^\| (?!구간|\*\*합계)[^|]+\| [^|]+\| (\d+) \| ([\d.]+)h \|$', s, re.M)
per  = re.findall(r'\*\*화면 (\d+) · ([\d.]+)시간\*\*', s)
print('구간', sum(int(a) for a, b in rows), sum(float(b) for a, b in rows))
print('장별', sum(int(a) for a, b in per),  sum(float(b) for a, b in per), len(per))
```

바뀌면 함께 고칠 곳: 커리큘럼 장별 표기·§3 표·§4 트랙 주차, 기획서 §6·§8, `docs/index.html` 분량 문구와 트랙 카드,
`book.js` 의 `BOOK`(`screens`, `hours`).

### 4.2 제약조건 커버리지

기획서의 C1~C16 이 교재에 최소 한 번 등장해야 한다. 전체 집필 후 확인.

```bash
for i in $(seq 1 16); do printf "C%-3s %s\n" "$i" "$(grep -l "C$i\b" docs/ch*.html | tr '\n' ' ')"; done
```

### 4.3 미룬 약속

```bash
grep -o '"later">[^<]*' docs/ch*.html
```

D1~D5 가 기획서 §3.3 의 장에서 실제로 갚아졌는지 확인한다. 산문의 "N장에서 다룹니다" 는 이 grep 에
안 걸리므로 `grep -n "N장" docs/ch*.html` 로 앞 장을 훑는다.

## 5. 자주 하는 실수

1. **행번호 어긋남** — §3.4.
2. **화면 삽입 위치 오류** — `kicker`·주석 번호·"화면 N" 상호 참조·`BOOK` 의 `screens` 를 다시 매긴다.
3. **정본과 본문의 DDL 불일치** — 본문 DDL 을 쓸 때 정본을 열어 둔다.
4. **`TERMS` 에 없는 `data-term`** — 툴팁이 조용히 안 난다. probe 의 `termsMissing`.
5. **`ready: true` 를 안 켜서** 목차에서 새 장이 회색으로 남는 것.
6. **`.later` 표시만 하고 안 갚는 것.**
7. **소문자 SQL 키워드** — 색이 안 칠해진다(§2).
8. **용어를 정의하기 전에 쓰는 것** — 뜻을 설명하는 화면이 이름이 붙은 화면보다 앞에 온다.
